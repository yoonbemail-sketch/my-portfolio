## Operational question

How do you speed up repetitive ATS applications without unsupervised autofill guessing — and without pasting job URLs into a black-box tool?

A local, human-in-the-loop assistant. It attaches to a user-selected Chrome tab, scores tailored resume versions against the JD, then autofills forms from a private resume hub — never submitting for you.

## Method

```text
Active Job Tab ──> JD Extractor ──> Semantic Matcher ──> Structured Gap Analysis
                                         ^
                                         |
                                  Resume Data Hub
                                         |
                                         v
Active ATS Tab ──> ATS Detection ──> Selector Strategy ──> Reviewed Form Fill
```

Streamlit UI: **Analyze → Apply → Autofill**. Matching gates on applyability first. Autofill uses soft ATS detection plus a shared field catalog (Workday, Greenhouse, SuccessFactors, Dayforce, Phenom, Oracle CX, and similar).

### Zero-URL contract

Playwright attaches over CDP to a user-managed Chrome instance and operates only on an explicitly selected tab. The UI never accepts a pasted job URL or JD text — navigation, auth, and final submit stay with the applicant.

### Human-supervised constraints

1. **No silent submit** — drafts are never posted without explicit approval
2. **Diff visibility** — reviewer sees mapped fields and unmatched ones for manual entry
3. **Preserve curated fields** — hub profile values are not overwritten by stale import prose
4. **Fail closed** — ambiguous ATS pages or mappings stop safely rather than guessing

## Status

Local HITL pipeline is implemented and documented on GitHub. Demo GIF clips are next; field-level validation table (ATS × fields filled × failure modes) will ship with those recordings.

## Limitations

- Not a fire-and-forget bot — unsupervised submit is intentionally out of scope
- ATS coverage is partial and DOM-signature based; new portals need catalog work
- LLM gap labels (`APPLY` / `APPLY_WITH_CAUTION` / `DO_NOT_APPLY` / `NEEDS_REVIEW`) still need a published accuracy sample
- Private resume hub stays local; this write-up does not expose personal data

## Tech stack

Python · Streamlit · Playwright (CDP) · Pydantic · BeautifulSoup · pypdf / python-docx · Gemini / Anthropic / OpenAI

## Design notes

- Separate durable applicant data from platform-specific selectors and model reasoning
- Validate LLM gap analysis with Pydantic
- Prefer importer-based refreshes over hardcoding resume prose that goes stale
- Detect ATS from local DOM signatures, not paid URL classifiers
