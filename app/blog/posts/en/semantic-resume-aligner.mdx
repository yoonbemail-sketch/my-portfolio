## Operational question

How can repetitive ATS applications be accelerated without unsupervised submission, and without pasting job URLs into a third-party service?

This project is a local Streamlit assistant. It attaches to a Chrome tab the user selects, ranks tailored resume versions against the job description, and fills recognized form fields from a private resume hub. Final submission remains with the applicant.

## Method

```text
Active Job Tab ──> JD Extractor ──> Matcher ──> Structured Gap Analysis
                                         ^
                                         |
                                  Resume Data Hub
                                         |
                                         v
Active ATS Tab ──> Soft ATS Hint ──> Catalog / Adapters ──> Reviewed Form Fill
```

The Streamlit UI follows **Analyze → Apply → Autofill**. Matching is deterministic by default: applyability is evaluated first, then resume versions are ranked. An optional LLM path is available via `MATCH_USE_LLM=1`. Autofill combines soft ATS detection with a shared field catalog (Workday, Greenhouse, SuccessFactors, Dayforce, Phenom, Jobvite, Oracle Cloud, and similar hosts). Experience adapters cover Workday, Phenom, and Dayforce page shapes.

### Zero-URL contract

Playwright attaches over CDP to a user-managed Chrome instance and operates only on an explicitly selected tab. The UI does not accept a pasted job URL or job-description text. Navigation, authentication, and submission stay under applicant control.

### Operating constraints

1. **No automatic submit** — the tool never posts an application without explicit user action
2. **Fill visibility** — mapped fields and unmatched fields are reported for manual completion
3. **Curated profile preservation** — hub profile fields are not overwritten by stale import text
4. **Soft ATS detection** — unknown hosts may still receive catalog fills; Submit is never clicked

## Status

The local pipeline is implemented and documented on GitHub. Demo GIF recordings and a field-level validation table (ATS × fields filled × failure modes) are forthcoming.

## Limitations

- Unsupervised end-to-end submission is out of scope
- ATS coverage is incomplete and based on DOM signatures; new portals require catalog or adapter work
- Recommendation labels (`APPLY` / `APPLY_WITH_CAUTION` / `DO_NOT_APPLY` / `NEEDS_REVIEW`) do not yet have a published accuracy sample
- The private resume hub remains local; this post does not include personal data

## Tech stack

Python · Streamlit · Playwright (CDP) · Pydantic · BeautifulSoup · pypdf / python-docx · optional Gemini / Anthropic / OpenAI

## Design notes

- Keep durable applicant data separate from platform DOM details and optional model calls
- Validate match results with Pydantic; keep the default path deterministic
- Prefer importer-based resume refreshes over hardcoded prose that drifts out of date
- Treat ATS detection from local DOM signatures as a hint, not a paid URL-classification gate
