## Data modeling (star schema)

모델 설계를 기록하는 섹션입니다.

- **Fact table** — 예: `fact_transactions` (sale price, quantity, timestamp, foreign keys)
- **Dimensions** — `dim_product`, `dim_brand`, `dim_seller`, `dim_date`, `dim_category`
- **Grain** — 완료된 리셀 거래 1건당 1행 (또는 선택한 grain)
- **Relationships** — dimension → fact 의 one-to-many; bidirectional filter는 필요한 경우만

```text
dim_brand ──┐
dim_product─┼──► fact_transactions
dim_date  ──┤
dim_seller──┘
```

## DAX optimization

측정값 설계와 성능 관련 메모:

- dimension 속성을 복제하는 calculated column보다 **star-schema relationship** 우선
- 필터가 동적으로 유지되어야 하면 로직을 **measures**에 두고 row-context calculated column은 최소화
- 동일 filter context 반복을 피하기 위해 **variables** (`VAR`) 사용
- Performance Analyzer / DAX Studio로 storage engine vs formula engine 시간 검증

예시 measure:

```dax
Total GMV =
SUMX (
    fact_transactions,
    fact_transactions[sale_price] * fact_transactions[quantity]
)
```
