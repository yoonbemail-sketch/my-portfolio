## Problem

반복적인 ATS 지원을 어떻게 줄이되, 검수 없는 자동 제출과 채용 URL을 외부 서비스에 붙여넣는 방식은 피할 수 있을까?

로컬 Streamlit 도구가 사용자가 선택한 Chrome 탭에 연결하고, 직무 설명에 맞춰 맞춤 이력서 버전을 순위한 뒤, 비공개 resume hub로 인식된 폼 필드를 채웁니다. 최종 제출은 지원자가 수행합니다.

[GitHub](https://github.com/yoonbemail-sketch/semantic-resume-aligner)

## Approach

1. **Analyze** — LinkedIn 채용 탭에서 JD를 추출하고, 지원 가능 여부를 먼저 평가한 뒤 이력서 버전을 순위화 (기본은 결정론적; LLM은 `MATCH_USE_LLM=1`)
2. **Apply** — 회사 ATS 탭을 사용자 통제 하에 열거나 포커스
3. **Autofill** — soft ATS 감지 + 공유 필드 카탈로그; Workday / Phenom / Dayforce 경력 어댑터
4. **Human review** — 채움/미채움 필드를 보고하고 Submit은 클릭하지 않음

운영 제약: 자동 제출 없음, 채움 결과 공개, import 시 큐레이션된 hub 필드 보존, 알 수 없는 호스트에도 카탈로그 채움 가능.

## Results

- 로컬 **Analyze → Apply → Autofill** 파이프라인이 구현되어 있으며 GitHub에 문서화됨
- 추천 라벨: `APPLY` / `APPLY_WITH_CAUTION` / `DO_NOT_APPLY` / `NEEDS_REVIEW`
- 카탈로그 대상: Workday, Greenhouse, SuccessFactors, Dayforce, Phenom, Jobvite, Oracle Cloud 등
- 데모 GIF와 필드 단위 검증 표(ATS × 채움 필드 × 실패 모드)는 추후 공개 예정

## Limitations

- 검수 없는 전 구간 자동 제출은 범위 밖입니다
- ATS 커버리지는 부분적이며 DOM signature에 의존합니다. 새 포털에는 카탈로그 또는 어댑터 작업이 필요합니다
- 추천 라벨의 공개 정확도 샘플은 아직 없습니다
- 비공개 resume hub는 로컬에 유지되며, 이 글에는 개인 데이터를 포함하지 않습니다

## Stack

Python · Streamlit · Playwright (CDP) · Pydantic · BeautifulSoup · pypdf / python-docx · 선택적 Gemini / Anthropic / OpenAI

**Zero-URL:** Playwright는 CDP로 사용자가 관리하는 Chrome에 연결하며, 명시적으로 선택한 탭에서만 동작합니다. UI는 채용 URL이나 JD 텍스트 붙여넣기를 받지 않습니다.

**설계 메모**

- 지원자 기본 데이터와 플랫폼 DOM·선택적 모델 호출을 분리합니다
- 매칭 결과는 Pydantic으로 검증하고, 기본 경로는 결정론적으로 유지합니다
- 쉽게 낡는 이력서 문구 하드코딩보다 importer 기반 갱신을 우선합니다
- 로컬 DOM signature 기반 ATS 감지는 힌트로 쓰고, 유료 URL 분류기를 전제로 하지 않습니다
