Kream 스니커즈 리셀 시장의 가격 신호와 사이즈·모델별 거래 패턴을 분석한 Operations Analyst 산출물입니다. 원천 거래 데이터를 적재·정규화한 뒤 Power BI 스타 스키마로 연결하고, 프리미엄·시즌성·매매 시그널까지 보는 리포트를 만들었습니다.

소스 코드와 Power BI workspace는 private로 유지합니다. 아래는 실제 모델·대시보드 기준 요약입니다.

## Problem

리셀 의사결정에는 “지금 이 모델·사이즈가 얼마에, 얼마나 자주 거래되는지”와 “정가 대비 프리미엄이 어디에 있는지”가 필요합니다. 화면의 최근 몇 건만으로는 시즌성, 사이즈 프리미엄, 배송 유형별 차이를 보기 어렵습니다.

## Pipeline overview

```text
Product page (model / size metadata)
        │
        ▼
Trade history collection (per size)
        │
        ▼
CSV per model · size  (+ resume / merge)
        │
        ▼
Validate · normalize dates · sales fact export
        │
        ▼
Power BI star schema (fact_sales + dims)
        │
        ▼
Dashboard pages (overview · price · signals · premium)
```

수집은 Playwright(CDP)로 사이즈·가격·날짜·배송유형을 저장하고, 병합·검증 후 Power BI fact로 넘깁니다.

## Data quality rules

| Rule | Why |
| --- | --- |
| Size prefix validation | 스크롤 중 다른 사이즈 행이 섞이지 않도록 검증 |
| Completion ratio (≥ 90%) | 기대 거래량 대비 충분히 모였는지 판정 |
| Relative date → absolute | `3시간 전` 등을 절대 날짜로 정규화 |
| Dedup on merge / update | 재수집 시 중복 제거, 신규분만 append |
| Master product cache | 브랜드·발매일·정가·카테고리를 `sneakers_info`에 캐시 |

## Data modeling (star schema)

실제 Power BI 모델 기준:

- **Fact** — `fact_sales`: 거래 grain (`SKU`, `Size`, `Size Type`, `Price`, `DeliveryType`, `DateKey`)
- **Dimensions** — `dim_product` (Model_No, Name_En/Kr, Brand, Category, Color, IsCollab, Release_Date, Retail_Price), `dim_brand`, `dim_date`
- **Relationships** — `dim_date[DateKey] → fact_sales`, `dim_product → fact_sales`, `dim_brand → dim_product` (및 brand→fact inactive 관계)
- **What-if / disconnected tables** — `Analysis Period`, `Profit Target %`, `Sales or Qty`, `Signal_Toggles` (BB Touch 등 시그널 기준 토글)

```text
dim_brand ──► dim_product ──► fact_sales
dim_date    ─────────────────► fact_sales

disconnected: Analysis Period · Profit Target % · Sales or Qty · Signal_Toggles
```

핵심 measure 예: `%Average Premium`, `Daily Avg Price`, Bollinger / RSI / Trend 기반 buy·sell condition, `KREAM Price Forecast`.

## Dashboard

공개 Publish-to-web 대신 리포트 페이지 구성을 정리합니다. (무료 라이선스 제약)

1. **Overview** — Total Sales / Quantity / %Average Premium KPI, 일자별 매출, 브랜드별 매출(Jordan · Nike · Adidas 상위), 카테고리·콜라보(`IsCollab`) 슬라이서, Max Premium 하이라이트
2. **Price trend** — Brand · Product · Size 필터와 Daily Avg Price by Date
3. **Signals** — Transaction Quantity vs Avg Price, Bollinger Band Analysis, Analysis Period / Profit Target % what-if, Master Buy·Sell 마커
4. **Premium by brand** — 브랜드별 %Average Premium, Retail vs Resale bubble(수량 크기), 주중/주말 프리미엄 matrix
5. **Size heatmap** — Size × Brand 프리미엄 heatmap(MM/US/W-MM), DeliveryType별 프리미엄 시계열

관측 포인트(전체 표본 기준):

- 표본 규모: 약 **3M** 건, Total Sales 약 **912bn** KRW, %Average Premium 약 **59%**
- 브랜드 매출 집중: Jordan → Nike → Adidas
- Jordan의 정가 대비 프리미엄이 특히 큼(브랜드 평균 대비 outlier)
- 사이즈·배송유형·콜라보 여부로 프리미엄이 갈림

## DAX / modeling notes

- dimension 속성은 relationship으로 가져오고, 동적 계산은 measure에 둠
- `%Average Premium`은 resale price와 `dim_product[Retail_Price]`를 비교
- Bollinger / RSI / Trend 시그널은 fact measure + what-if 파라미터로 기간·목표 수익률을 조절
- `Sales or Qty` disconnected table로 동일 비주얼의 값 축을 전환

```dax
%Average Premium =
DIVIDE (
    [Daily Avg Price] - SELECTEDVALUE ( dim_product[Retail_Price] ),
    SELECTEDVALUE ( dim_product[Retail_Price] )
)
```

## Results

모델×사이즈 거래 이력을 적재하고 `fact_sales` 스타 스키마로 연결한 뒤, 프리미엄·가격 추이·볼린저 시그널 페이지까지 구성된 리포트를 만들었습니다. 공개 임베드는 라이선스 제약으로 생략하고, 포트폴리오에는 모델 구조와 대시보드 구성·insight로 제시합니다.
