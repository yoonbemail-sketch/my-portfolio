Kream 스니커즈 리셀 시장의 가격 신호와 사이즈·모델별 거래 패턴을 분석한 Operations Analyst 산출물입니다. CDP 기반 거래 수집기가 사이즈 단위로 재개·갱신·검증한 뒤 스타 스키마와 Power BI 대시보드로 프리미엄·시즌성·매매 시그널까지 연결합니다.

소스 코드와 Power BI workspace는 private로 유지합니다. 아래는 수집 엔진 설계, 데이터 규칙, 모델·리포트 페이지 기준 요약입니다.

## Problem

리셀 의사결정에는 “지금 이 모델·사이즈가 얼마에, 얼마나 자주 거래되는지”와 “정가 대비 프리미엄이 어디에 있는지”가 필요합니다. 화면의 최근 몇 건만으로는 시즌성·사이즈 프리미엄·배송 유형 차이를 보기 어렵고, 긴 infinite-scroll 이력은 한 번 긁고 끝내기 어렵습니다. 수집은 rate limit·세션 만료·부분 수집을 전제로 설계되어야 합니다.

## Collection engine

핵심은 일회성 크롤이 아니라 **stateful collector**입니다. Playwright가 이미 로그인한 Chrome에 CDP(`localhost:9222`)로 붙고, 상품마다 아래를 탑니다.

```text
Queue / product page
        │
        ▼
Identify model · cache or analyze sizes (expected volume)
        │
        ▼
Collect missing sizes only (95% = complete)
        │
        ▼
Per-size scroll loop → CSV (Size, Price, Date, DeliveryType)
        │
        ▼
Merge (+ SKU) → sales fact → Power BI
```

실행 축: 단일 상품 인터랙티브, 큐 배치 처리, 현재 탭에서 모델·URL·이름을 뽑아 큐에 넣는 adder.

### 사이즈별 수집 모드

| Mode | When | Behavior |
| --- | --- | --- |
| Full | 최종 CSV 없음 | newest-first로 `_W` 임시파일 수집 → 성공 시 rename |
| Update | 최종 CSV 있음 | 신규만 수집, 배치 중복 ≥80%면 중단, unique를 앞에 prepend |
| Resume | 중단된 수집 | `_W` / `_W_reverse`가 충분히 크면 재개, 아니면 fresh |
| Bottom gap fill | 위는 최신인데 아래(오래된 구간) 비어 있음 | oldest-first로 구멍 메움 |
| Reverse-append | `_W`에서 재개 | oldest-first로 모으다 기존 oldest date와 overlap되면 합침 |

완료 판정은 단순 row count가 아닙니다. 목표 도달, 기대량의 약 90%, 또는 batch(50) 경계가 아닌 자연 종료를 같이 봐 soft-ban과 “진짜 끝”을 구분합니다.

### 루프에 들어간 복구 로직

| Signal | Response |
| --- | --- |
| Soft-ban (신규 row 없음) | progress별 no-change 임계 → exponential backoff → reload → 남은 사이즈 재시도 |
| 세션 만료 | 로그인 URL/모달 감지 → 재로그인 → 현재 사이즈부터 재시도 |
| 스크롤 stuck (비정상적으로 빠름) | scroll-up으로 unstick (횟수 제한) → 실패 시 error |
| 잘못된 사이즈 행 | JS size-prefix 검사 → `CORRUPTED` abort |
| 날짜 오염 | invalid date row 필터 후 저장 |
| 사이즈 분석 품질 | 동일 거래량·중복 키·0 과다면 재분석 |
| 초고거래량 | 안전 상한 초과 사이즈 스킵 |

배치 모드는 같은 파이프라인을 무인으로 돌립니다. `scrape_queue.csv` 읽기 → 미수집 사이즈 수집 → 성공 시 merge·큐 제거 → soft-ban/skip/배치 요약 알림.

## Data quality rules

| Rule | Why |
| --- | --- |
| Size prefix validation | 스크롤 중 다른 사이즈 행이 섞이지 않도록 검증 |
| Completion ratio (≥ 90% / 95%) | soft-complete vs missing-only “이미 모음” 판정 |
| Relative date → absolute | fact export 시 `3시간 전` 등을 파일 mtime 기준으로 절대 날짜화 |
| Dedup on merge / update | 재수집 시 중복 제거, 신규분만 append |
| Master product cache | 브랜드·발매일·정가·사이즈분포를 `sneakers_info`에 캐시 |
| Dual size keys | 같은 KR mm / 다른 US 라벨 구분 (예: `250_W8`) |

## From CSV to fact

Grain은 항상 **거래 1건**입니다.

- 사이즈별: `CSV/{MODEL}/{MODEL}_{size}.csv`
- 모델 통합: `{MODEL}_merged.csv` (+ `SKU`)
- 전 모델: `sales_fact.csv` (`SKU`, `Size`, `Price`, `Date`, `DeliveryType`) — 기본 증분 append, full rebuild 옵션

## Data modeling (star schema)

Power BI 모델 기준:

- **Fact** — `fact_sales`: 거래 grain (`SKU`, `Size`, `Size Type`, `Price`, `DeliveryType`, `DateKey`)
- **Dimensions** — `dim_product` (Model_No, Name_En/Kr, Brand, Category, Color, IsCollab, Release_Date, Retail_Price), `dim_brand`, `dim_date`
- **Relationships** — `dim_date[DateKey] → fact_sales`, `dim_product → fact_sales`, `dim_brand → dim_product` (및 brand→fact inactive)
- **What-if / disconnected** — `Analysis Period`, `Profit Target %`, `Sales or Qty`, `Signal_Toggles`

```text
dim_brand ──► dim_product ──► fact_sales
dim_date    ─────────────────► fact_sales

disconnected: Analysis Period · Profit Target % · Sales or Qty · Signal_Toggles
```

핵심 measure: `%Average Premium`, `Daily Avg Price`, Bollinger / RSI / Trend buy·sell condition, `KREAM Price Forecast`.

## Dashboard

공개 Publish-to-web 대신 리포트 페이지 구성입니다. (무료 라이선스 제약)

1. **Overview** — Total Sales / Quantity / %Average Premium KPI, 일자별 매출, 브랜드별 매출(Jordan · Nike · Adidas 상위), 카테고리·`IsCollab` 슬라이서
2. **Price trend** — Brand · Product · Size 필터와 Daily Avg Price by Date
3. **Signals** — Quantity vs Avg Price, Bollinger Band Analysis, period / profit target what-if, Master Buy·Sell 마커
4. **Premium by brand** — 브랜드별 %Average Premium, Retail vs Resale bubble, 주중/주말 프리미엄 matrix
5. **Size heatmap** — Size × Brand 프리미엄 heatmap(MM/US/W-MM), DeliveryType별 프리미엄 시계열

관측 포인트(전체 표본):

- 약 **3M** 건, Total Sales 약 **912bn** KRW, %Average Premium 약 **59%**
- 브랜드 매출 집중: Jordan → Nike → Adidas
- Jordan의 정가 대비 프리미엄이 특히 큼
- 사이즈·배송유형·콜라보 여부로 프리미엄이 갈림

## DAX / modeling notes

```dax
%Average Premium =
DIVIDE (
    [Daily Avg Price] - SELECTEDVALUE ( dim_product[Retail_Price] ),
    SELECTEDVALUE ( dim_product[Retail_Price] )
)
```

- dimension 속성은 relationship, 동적 계산은 measure
- Bollinger / RSI / Trend는 fact measure + what-if 기간·목표 수익률
- `Sales or Qty`로 동일 비주얼 값 축 전환

## Results

사이즈 단위로 재개·증분 갱신이 가능한 stateful 거래 수집기를 만들고, sales fact로보낸 뒤 `fact_sales` 스타 스키마와 프리미엄·가격 추이·볼린저 시그널 리포트까지 연결했습니다. 공개 임베드는 라이선스 제약으로 생략하고, 포트폴리오에는 수집 엔진·모델·대시보드 구성으로 제시합니다.
