Kream 스니커즈 리셀 시장의 가격·거래 패턴을 분석한 Operations Analyst 프로젝트입니다. 사이즈별 거래내역을 모으고, 정리한 뒤 Power BI에서 프리미엄과 시그널을 봅니다.

소스 코드와 Power BI workspace는 private입니다.

## Problem

리셀에는 “이 모델·사이즈가 얼마에, 얼마나 자주 팔리는지”와 “정가 대비 프리미엄”이 필요합니다. 상품 페이지의 최근 몇 건만으로는 시즌성이나 사이즈별 차이를 보기 어렵습니다. 거래 이력은 길고, 중간에 막히거나 끊기기 쉬워서 **한 번에 다 긁는 방식**으로는 부족합니다.

## How collection works

이미 로그인한 Chrome에 Playwright로 붙어서, 상품마다 아래 순서로 돕니다.

```text
상품 페이지 / 큐
    → 모델 확인, 사이즈별 기대 거래량 파악
    → 아직 덜 모인 사이즈만 수집
    → 사이즈·가격·날짜·배송유형을 CSV로 저장
    → 모델별로 합치고 sales fact로보내 Power BI에 연결
```

- **단일 실행:** 지금 보고 있는 상품 하나
- **배치 실행:** 큐에 쌓인 상품을 순서대로 자동 처리
- **큐 추가:** 브라우저 탭에서 모델·URL을 뽑아 목록에 넣기

### 끊겨도 이어서, 있으면 신규만

처음이면 최신 거래부터 끝까지 모읍니다.  
이미 파일이 있으면 **새로 생긴 거래만** 붙이고, 예전에 모았던 구간과 겹치면 멈춥니다.  
중간에 끊기면 임시 파일에서 **이어서** 돌리고, 위쪽(최신)은 채워졌는데 아래쪽(오래된 구간)이 비어 있으면 그쪽만 채웁니다.

“다 모였다”는 건수만이 아니라, 화면에 나온 기대 거래량의 대부분(약 90%)에 가까우면 끝난 것으로 봅니다. 잠시 막혀 데이터가 안 늘어난 것과 진짜 끝을 구분하기 위해서입니다.

### 막히면 어떻게 하냐

- 스크롤해도 새 거래가 안 나오면 잠시 기다렸다가 페이지를 새로고침하고, 남은 사이즈부터 다시 시도합니다.
- 로그인이 풀리면 다시 로그인한 뒤 이어서 수집합니다.
- 스크롤이 멈춘 것처럼 보이면 위로 올려 풀고, 안 되면 그 사이즈는 넘깁니다.
- 다른 사이즈 행이 섞이거나 날짜가 이상하면 그 행은 버리고, 필요하면 그 사이즈 수집을 중단합니다.
- 사이즈별 거래량이 전부 같거나 비정상적으로 비어 있으면 사이즈 분석을 다시 합니다.
- 거래량이 너무 큰 사이즈는 안전하게 건너뜁니다.

배치로 돌릴 때는 큐를 읽고 → 덜 모인 사이즈만 채우고 → 끝나면 파일 합친 뒤 큐에서 빼고 → 막히거나 스킵된 건 알림으로 남깁니다.

## 데이터를 깨끗이 유지하는 방법

- 사이즈가 맞는지 검사해서 다른 사이즈 거래가 섞이지 않게 합니다.
- 기대 거래량과 비교해 “충분히 모였는지” 판단합니다.
- `3시간 전` 같은 상대 날짜는 fact로보낼 때 실제 날짜로 바꿉니다.
- 다시 돌릴 때는 중복을 빼고 신규만 붙입니다.
- 브랜드·발매일·정가·사이즈 분포는 마스터 파일에 캐시해 둡니다.
- 같은 mm인데 US 표기가 다른 경우(예: 남성/여성)는 사이즈 키를 구분해 저장합니다.

## CSV에서 fact까지

한 행 = 거래 한 건입니다.

1. 사이즈별 CSV
2. 모델 하나로 합친 파일 (+ SKU)
3. 전 모델 `sales_fact` (SKU, Size, Price, Date, DeliveryType)

## Data modeling (star schema)

Power BI에서는 거래 fact에 상품·브랜드·날짜 dimension을 붙입니다.

- **Fact** — `fact_sales` (SKU, Size, Price, DeliveryType, DateKey …)
- **Dimensions** — `dim_product`, `dim_brand`, `dim_date`
- **What-if** — 분석 기간, 목표 수익률, Sales/Qty 전환, 시그널 토글

```text
dim_brand ──► dim_product ──► fact_sales
dim_date    ─────────────────► fact_sales
```

핵심 measure: `%Average Premium`, `Daily Avg Price`, Bollinger / RSI / Trend 시그널, `KREAM Price Forecast`.

## Dashboard

공개 임베드 대신 리포트 페이지 구성입니다. (무료 라이선스 제약)

1. **Overview** — 매출·수량·평균 프리미엄 KPI, 일자·브랜드별 매출
2. **Price trend** — 브랜드·상품·사이즈별 일평균가
3. **Signals** — 거래량 vs 가격, 볼린저 밴드, 기간·목표 수익률 what-if
4. **Premium by brand** — 브랜드 프리미엄, 정가 vs 리셀, 주중/주말
5. **Size heatmap** — 사이즈×브랜드 프리미엄, 배송유형별 추이

관측 포인트:

- 약 **3M** 건, 매출 약 **912bn** KRW, 평균 프리미엄 약 **59%**
- 매출 집중: Jordan → Nike → Adidas
- Jordan의 정가 대비 프리미엄이 특히 큼
- 사이즈·배송유형·콜라보 여부로 프리미엄이 갈림

## DAX / modeling notes

```dax
%Average Premium =
DIVIDE (
    [Daily Avg Price] - SELECTEDVALUE ( dim_product[Retail_Price] ),
    SELECTEDVALUE ( dim_product[Retail_Price] )
)
```

- 속성(브랜드, 정가 등)은 relationship으로 가져오고, 계산은 measure에 둡니다.
- 시그널은 fact measure + what-if(기간·목표 수익률)로 조절합니다.

## Stack

| Layer | Tools |
| --- | --- |
| Collection | Python, Playwright (Chrome에 연결) |
| Ops | 이어받기, 신규만 갱신, 막힘 대기·재시도, 자동 재로그인 |
| ETL | 사이즈별 CSV → merge → `sales_fact` |
| Analytics | Power BI (star schema, DAX, what-if) |

## Results

사이즈별로 이어서 모으고 신규만 갱신할 수 있는 거래 수집기를 만들고, sales fact와 Power BI 리포트(프리미엄·가격·시그널)까지 연결했습니다. 공개 임베드는 라이선스 제약으로 생략하고, 이 페이지에서 수집 방식과 대시보드 구성을 정리합니다.
