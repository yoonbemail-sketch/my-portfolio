## Problem

리셀에는 “이 모델·사이즈가 얼마에, 얼마나 자주 팔리는지”와 “정가 대비 프리미엄”이 필요합니다. 상품 페이지의 최근 몇 건만으로는 시즌성이나 사이즈별 차이를 보기 어렵습니다. 거래 이력은 길고 중간에 끊기기 쉬워, 한 번에 전부 수집하는 방식은 부족합니다.

## Approach

1. **Collect** — 로그인한 Chrome에 Playwright 연결; 단일 / 배치 / 큐 모드로 사이즈별 거래를 CSV에 수집
2. **Resume & update** — 신규 거래만 증분, 임시 파일에서 이어받기, 오래된 구간 갭 채움; 기대 거래량의 약 90%에 가까우면 완료
3. **Clean** — 사이즈 일치 검사, 상대→절대 날짜, 중복 제거, 마스터 캐시, 사이즈 키 분리
4. **Model** — 사이즈별 CSV → 모델 merge → `sales_fact` → Power BI star schema (fact + product / brand / date + what-if)

대시보드는 **어떤 모델×사이즈를 지켜볼지 / 피할지 / 다시 볼지**를 보기 위한 것이지, 매수 버튼이 아닙니다.

## Results

샘플 규모: 약 **3M** 건, 매출 약 **9,120억 원**(₩912bn), 평균 프리미엄 약 **59%**.

- 매출 집중: Jordan → Nike → Adidas; Jordan은 정가 대비 프리미엄 아웃라이어
- 사이즈·배송유형·콜라보 여부로 프리미엄이 갈림
- **Monitor:** 거래량이 있고 프리미엄이 높으며 사이즈 분리가 분명한 경우
- **Avoid / wait:** 이력이 얇거나 짧은 구간에만 좋아 보이는 프리미엄
- **Revisit:** 주중·주말 갭, 배송유형 변화로 기대 순이익이 달라질 때

## Limitations

- 수집기 소스는 private; 공개 산출물은 Publish-to-web 리포트(인증 없음, 완전 공개)
- 커버리지·최신성은 큐에 넣은 상품과 마지막 incremental run 시점에 좌우됨
- 프리미엄·볼린저형 시그널은 과거 거래를 서술할 뿐, 캘리브레이션된 가격·재고 모델이 아님
- Publish-to-web은 민감 데이터에 부적합; 이 데모는 포트폴리오 열람용 분석 모델

## Stack

| Layer | Tools |
| --- | --- |
| Collection | Python, Playwright (Chrome에 연결) |
| Ops | 이어받기, 신규만 갱신, 막힘 대기·재시도, 자동 재로그인 |
| ETL | 사이즈별 CSV → merge → sales_fact |
| Analytics | Power BI (star schema, DAX, what-if) |

## Notes

<details>
<summary>수집 운영, star schema, DAX</summary>

**수집 단계:** 상품/큐 → 모델·사이즈별 기대 거래량 → 미완료 사이즈만 → CSV → merge → sales fact → Power BI.

**장애 대응:** 대기/새로고침/재시도; 세션 만료 시 재로그인; 스크롤 고정 시 넛지; 잘못된 사이즈·날짜 행 제거; 사이즈 분석 재실행; 거래량이 극단적으로 큰 사이즈는 스킵.

**Star schema**

| 테이블 | 역할 |
| --- | --- |
| fact_sales | 거래 한 건 (SKU, Size, Price, DeliveryType, DateKey …) |
| dim_product | 모델·이름·카테고리·정가·발매일 |
| dim_brand | 브랜드 |
| dim_date | 날짜 |
| What-if | 분석 기간, 목표 수익률, Sales/Qty, 시그널 토글 |

```dax
%Average Premium =
DIVIDE (
    [Daily Avg Price] - SELECTEDVALUE ( dim_product[Retail_Price] ),
    SELECTEDVALUE ( dim_product[Retail_Price] )
)
```

속성은 relationship으로 가져오고, 계산은 measure에 둡니다. 시그널은 fact measure + what-if(기간·목표 수익률)로 조절합니다.

</details>
